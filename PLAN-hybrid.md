# Hybrid mode: Claude is the brain, Codex is the hands (plan, 2026-10-28)

Owner decision (2026-10-28): all coding goes to Codex. Claude plans, researches, decides, writes the words and gives Codex
super explicit orders. Codex does not think: it executes the order, nothing more. Claude verifies and integrates.
Companion doc for the general doctrine: `~/claude-codex-hybrid-workflow.md` (§0 and §5 apply to the fleet as well).

## Why (measured, not guessed)

- A Claude `-p` job that edits files burns **0.7 to 1.4 million input tokens** per draft (it re-reads the repo every turn). That is
  what hit the 5-hour session limit with 40+ clicked jobs. A planning-only Claude call with the context handed to it is ~30 to 60k.
- Codex runs on the ChatGPT subscription (`codex login status` = "Logged in using ChatGPT"), a separate allowance from Claude.
- Claude's value is judgment: which topic, what is true, what to say, what to refuse. Typing a TS object into an array is not judgment.

## Roles

| | Claude (`claude -p`, subscription) | Codex (`codex exec`, ChatGPT login) |
|---|---|---|
| Does | researches (web), decides, writes copy and translations, writes the **work order**, reviews the final diff | executes the work order: creates/edits the exact files in the order, nothing else |
| Tools | WebSearch, WebFetch only. **No Read/Edit/Write/Bash** (the orchestrator hands it the context it needs) | workspace-write sandbox on the agents' worktree, no network, ephemeral |
| Never | edits files, reads the repo on its own | plans, researches, "improves" text, touches files not in the order, commits, pushes |
| Checks it | the final diff against the order and the site rules (reviewer pass) | nothing: deterministic checks (typecheck, tests, `postEdit`, `validate`, verbatim check) judge it |

Analyst and researcher stay 100% Claude (they only think). Crawl/collect/publish stay plain code.

## The pipeline (replaces the single `claude -p` that did everything)

```
 click / schedule
      |
 [1 PLAN]    Claude, web tools only. Gets: topic, brief, rules, SEO playbook, mini-audit, and an EXAMPLE of the site's own post
             (the orchestrator extracts it). Returns ONE JSON work order (see below). No file access.
      |
 [2 EXECUTE] Codex, write sandbox on the worktree. Prompt = the order, rendered by orders.orderPrompt(): numbered steps with exact
             text, exact anchors, forbidden paths, "do nothing else". Output: edited files.
      |
 [3 VERIFY]  deterministic, no model: path allowlist, postEdit (regenerate derived files), typecheck/tests, validate(), copy lint,
             VERBATIM check (every string the order says must appear is in the diff). Fail -> [3b].
 [3b FIX]    Codex again with a fix order generated BY CODE from the error text ("fix only this, change nothing else").
             Still failing -> back to [1] ONCE with the error appended (Claude re-plans). Still failing -> draft rejected.
      |
 [4 REVIEW]  Claude, no tools. Gets the order, the rules and the diff (capped). Returns {ok, problems[], blocking}. blocking -> rejected.
             Non-blocking problems are shown on the approval card. The human approval gate stays exactly as it is.
      |
 approval -> publish (unchanged)
```

Fixer (code changes) gets a scout step first because Claude cannot see the repo: **[0 SCOUT]** Codex, read-only, is asked for the
file, line and 10-line excerpt behind each finding; Claude plans from that report; then the same 2 to 4 steps.

## Work order (the contract between the brain and the hands)

```json
{
  "title": "short",
  "steps": [
    { "n": 1, "file": "src/data/blog-posts.ts", "do": "insert-before",
      "anchor": "];\n",                       // exact text that occurs exactly ONCE in the file (the order lists the occurrence rule)
      "text": "  {\n    slug: \"...\",\n ... },\n",   // EXACT text to place, character for character
      "note": "append as the last element of blogPosts" },
    { "n": 2, "file": "public/sitemap.xml", "do": "insert-after", "anchor": "...", "text": "..." }
  ],
  "mustContain": ["every string that has to be present verbatim in the result"],
  "forbiddenPaths": ["src/routes/", "..."],
  "doneWhen": "plain sentence"
}
```
Allowed `do`: `create`, `replace` (anchor -> text), `insert-after`, `insert-before`, `append`, `delete` (anchor block). Paths are repo-relative,
no `..`. An anchor that is missing or ambiguous is a stop condition for Codex ("report BLOCKED: <why>, change nothing").

## Codex prompt rules (what makes it "just execute")

1. First line: "You are an executor, not a designer. Do exactly the numbered steps. Do not improve, reformat, rename, refactor or add anything."
2. Steps verbatim. Text in a fenced block, copied character for character, including whitespace.
3. Only the files named in the steps may change. If a step cannot be done exactly (anchor missing or twice), stop and write `BLOCKED: <reason>` as the last line; change nothing.
4. No commands except read-only ones (`ls`, `cat`, `grep`, `git diff`, `git status`). No installs, no network, no git writes.
5. Last message = `DONE` plus one line per step (`1 ok`, `2 ok`...). Nothing else.

## What stays, what changes in the code

Stays: scheduler, queue, **pause/resume**, approvals, publish, per-site `postEdit`/`validate`/`regenerateFrom` hooks, dashboard, pm2.

New (written by Codex from Claude's tickets, then verified by Claude):
- `runner.ts`: `runCodex` (subscription check, env allowlist, nice 19, sandbox, timeout, usage-limit detection), next to `runClaude`.
- `orders.ts`: `WorkOrder` type, `parseOrder` (validates what Claude returned), `orderPrompt`, `fixPrompt`, `verbatimCheck`.
- `agents.ts`: hybrid `draftTopic` (writer + improver) with the pipeline above; hybrid fixer with scout. `AGENT_EXECUTOR=hybrid|claude`, default `hybrid`; if Codex is not logged in on the ChatGPT plan the fleet falls back to `claude` and says so on the dashboard.
- `sites.ts`: per-site `example(wt)` (the post Claude imitates) and `wiringNotes` (where a post must be wired in, as Claude-facing text).

## Risks and the answers

| Risk | Answer |
|---|---|
| Codex "helpfully" rewrites copy | orders carry exact text; `mustContain` verbatim check on the diff; reviewer pass; human approval |
| Claude writes a malformed order | `parseOrder` rejects before Codex runs; one re-plan with the validation error |
| Anchor drift (repo changed) | missing/ambiguous anchor = `BLOCKED`, draft retried once from [1] with fresh context |
| Codex hits its own limit | same park-and-retry as Claude (limit detection in `runCodex`) |
| Prompt injection from web pages | Claude has web tools but no file/shell tools; Codex has no network; orders are validated and paths allowlisted |
| Quality drop vs all-Claude | rollout gate below, `AGENT_EXECUTOR=claude` is one switch away |

## Rollout (the fleet stays PAUSED until step 4 passes)

1. Tickets T1 (runner), T2 (orders), T3 (pipeline wiring) go to Codex, one at a time, each with its own tests; Claude verifies each (`git status`, `tsc`/tests, reads the diff).
2. Unit tests with a fake `codex` on PATH (no real calls).
3. One REAL end-to-end on a scratch clone of Vexon (real Claude plan + real Codex execute + real checks), nothing pushed.
4. Compare to the old all-Claude draft for the same topic (tokens, time, diff quality). If equal or better: Resume. Otherwise fix the orders, not the mode.
5. Resume from the dashboard; watch the first 3 drafts per site; record tokens per stage in `agent_runs` (planner/executor/reviewer separately).
